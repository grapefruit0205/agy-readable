# agy-readable

[English](README.md) · **한국어**

**Claude의 한국어 답변을 한눈에 읽히는 한국어로 바꿔 줍니다.** Claude Code의 한국어 답변은 읽기 어려울 때가 많습니다. 문장이 길고, 번역투이고, 요점이 중간에 묻힙니다. agy-readable은 Claude Code 플러그인입니다. 답변이 끝나면 [agy](https://antigravity.google/)(Antigravity CLI)의 Gemini 3.8 Flash에 넘겨, 제목·요약·질문과 답처럼 구조가 분명한 쉬운 한국어로 다시 구성하게 합니다.

자유롭게 다시 쓰면 읽기는 좋아지지만, 원문에 없는 이유나 센 표현이 끼어들 수 있습니다. 그래서 두 번 부릅니다. 먼저 자유롭게 다시 쓰게 하고, 이어서 그 글을 원문과 한 문장씩 맞춰 보게 해서 틀린 문장만 고치게 합니다([두 번째 단계](#두-번째-단계-원문과-맞춰-고치기)).

코드, 링크, URL, 파일 경로는 agy에 보내지 않습니다. 자리 표시로 바꿔 보내고, 돌아온 글에 원래 내용을 글자 그대로 되돌려 넣습니다. 숫자와 '추정', '확인된 사실' 같은 단서는 글에 남겨 두되, 원문에 있는 것은 하나도 빠지면 안 되고 새 숫자가 생겨도 안 됩니다. 검사를 통과하지 못하거나 agy가 느리거나 실패하면, Claude가 쓴 원문을 그대로 보여 주고 이유를 한 줄 붙입니다. 무엇을 검사하고 무엇은 못 잡는지는 [무엇을 검사하나](#무엇을-검사하나)에 있습니다.

바뀌는 것은 화면에 보이는 글뿐입니다. Claude가 기억하는 대화와 다음 턴의 맥락은 원문 그대로입니다.

## 필요한 것

- Claude Code **2.1.280 이상** (`MessageDisplay` 훅). 터미널과 데스크톱 앱 모두 됩니다.
- **Linux 또는 macOS**. Windows는 지원하지 않습니다(보조 프로세스가 유닉스 소켓을 씁니다). Windows에서는 훅이 아무것도 하지 않아 답변이 그대로 보입니다.
- `python3` 또는 `python`으로 실행되는 **Python 3.8 이상**
- PATH에 있는 **agy(Antigravity CLI)**. 본인 Antigravity 계정으로 로그인되어 있어야 합니다. 로그인이 안 되어 있으면 agy-readable이 Claude Code 안에서 로그인을 요청합니다([Antigravity 로그인](#antigravity-로그인)).
  - agy는 헤드리스로 동작합니다. Antigravity가 OS 키링에 저장해 둔 OAuth 토큰으로 로그인합니다.
  - agy-readable은 PATH에 있는 `agy`를 실행할 뿐입니다. 인증 정보를 읽거나 복사하거나 저장하지 않고, 플러그인에 들어 있는 인증 정보도 없습니다.
  - 그래서 설치한 사람마다 자기 로그인과 자기 할당량으로 돌아갑니다.

## 설치

```
claude plugin marketplace add grapefruit0205/agy-readable
claude plugin install agy-readable@agy-readable
```

Claude Code 안에서는 `/plugin marketplace add grapefruit0205/agy-readable` 다음에 `/plugin install agy-readable@agy-readable`을 입력합니다. 설치 후 새 세션을 시작하세요.

- 업데이트: `claude plugin marketplace update agy-readable` 다음에 `claude plugin update agy-readable@agy-readable`
- 잠시 끄기: `claude plugin disable agy-readable@agy-readable`
- 제거: `claude plugin uninstall agy-readable@agy-readable`

## Antigravity 로그인

agy-readable은 agy 자체의 로그인 절차를 씁니다. 비밀번호나 토큰은 다루지 않습니다. agy가 로그인되어 있지 않으면 이렇게 진행됩니다.

1. 다음 답변이 원문 그대로 나오고, 아래에 *Antigravity 로그인이 필요합니다…* 안내가 붙습니다. 브라우저에 Google 로그인 페이지가 열립니다(macOS, 데스크톱이 있는 Linux). 안내에도 링크가 있습니다.
2. 로그인하고 권한을 허용합니다. 그러면 페이지에 `4/`로 시작하는 코드가 나옵니다.
3. 그 코드만 Claude Code 입력창에 붙여넣고 Enter를 누릅니다. **안내가 나온 뒤 60초 안에** 해야 합니다(agy에 정해진 제한).
   - agy-readable이 입력창에서 코드를 가져가므로 Claude에게는 전달되지 않습니다.
   - 코드를 agy에 넘긴 뒤 *Antigravity 로그인이 끝났습니다*라고 알려 줍니다. 다음 답변부터 다듬어집니다.

agy 시작이 늦어 10초 안에 로그인 주소가 나오지 않으면, 로그인을 아직 준비 중이라고 알리고 잠시 뒤 `/agy-readable:login`을 입력하라고 합니다. 준비 중인 로그인은 계속 진행되고, 그 명령이 이어받습니다.

60초가 지났거나 코드가 틀리면 그렇다고 알려 주고 새 로그인 페이지를 엽니다. 안내를 그냥 넘긴 경우, 10분 동안은 답변마다 페이지를 다시 열지 않습니다. 언제든 입력창에 `/agy-readable:login`을 입력해 다시 시작할 수 있습니다. 이 컴퓨터에 브라우저가 없다면(SSH 접속 등) 터미널에서 `agy`를 한 번 실행해도 같은 방법으로 로그인됩니다.

동작 방식은 이렇습니다.
- agy는 입력이 터미널일 때만 로그인 절차를 보여 줍니다. 그래서 데몬이 가상 터미널에서 `agy -p ok`를 실행하고, agy가 출력한 주소를 보여 준 뒤, 붙여넣은 코드를 그 터미널에 입력합니다.
- 코드를 토큰으로 바꾸고 OS 키링에 저장하는 일은 agy가 평소처럼 합니다. 이때 한 번 보내는 `ok` 요청이 유일한 모델 호출입니다.
- Claude Code는 막힌 입력을 "Original prompt"로 화면에 다시 보여 줍니다. 코드는 한 번만 쓸 수 있고 그 로그인 시도에만 묶여 있어서, 그 뒤에는 쓸모가 없습니다.
- `AGY_READABLE_BROWSER=none`으로 두면 링크만 보여 줍니다. 명령을 넣으면 그 명령으로 엽니다.

## 화면에서 보이는 것

Claude가 답을 쓰는 동안에는 답변이 보이지 않습니다. 다 쓰고 나면 다시 쓴 답변이 한 번에 나타납니다.

다음 답변은 손대지 않고 Claude가 쓴 그대로 보여 줍니다.

- 300자보다 짧거나 6,000자보다 긴 답변
- 한국어가 없는 답변
- 대부분이 코드인 답변 (코드 블록이 60%를 넘는 경우)

다시 쓴 답을 쓰지 않을 때는 원문 아래에 `_(다듬기 생략: agy 응답이 60초를 넘음 · 원문 표시)_` 같은 한 줄이 붙습니다. 이유는 다음 중 하나입니다.

- agy가 로그인되어 있지 않음 (위 "Antigravity 로그인" 참고)
- agy가 제한 시간을 넘김
- agy가 오류를 냄 (예: 백엔드 503)
- PATH에 agy가 없음
- 다시 쓴 답이 다시 시도까지 검사를 통과하지 못함 ([무엇을 검사하나](#무엇을-검사하나)). 설명에 이유가 적힙니다. 예: `코드·링크·경로 일부가 빠짐: …`, `숫자가 빠지거나 바뀜: -3`, `원문에 없는 숫자가 생김: 5`, `단서가 빠짐: 추정`, `결과 길이가 비정상`

검사에 걸려도 바로 원문을 보여 주지 않습니다. 빠진 숫자·코드·단서는 두 번째 단계에서 되살리게 하고, 원문에 없는 숫자·경로·코드는 빼게 하고, 그래도 걸리면 무엇이 틀렸는지(예: `숫자가 빠지거나 바뀜: 4`) agy에 알려 주고 처음부터 한 번 더 다시 쓰게 합니다.
- 제한 시간 안에, 앞의 시도만큼 걸릴 시간이 남아 있을 때만 합니다. 모자라면 기다리게 하지 않고 바로 원문을 보여 줍니다.
- 다시 시도도 걸리면 설명이 `숫자가 빠지거나 바뀜: 4 (다시 시도해도 같음)`이나 `… · 다시 시도: agy 응답이 60초를 넘음`처럼 붙습니다.

답변 조각 하나가 훅에 끝내 도착하지 않으면 답변을 다시 쓰지 않습니다. Claude Code는 표시 훅을 최대 3개까지 동시에 실행하고, 그중 하나가 실패할 수 있습니다.
- 도착한 부분만 보여 주고, 빠진 자리에 경고를 붙입니다.
- 전체 답변은 Claude의 대화 기록과 `/export`에 있습니다.
- 늦게 오는 조각은 최대 10초까지 기다린 뒤에 빠졌다고 판단합니다.

## 두 번째 단계: 원문과 맞춰 고치기

자유롭게 다시 쓴 글에는 원문에 없는 이유, 예시, 센 표현("완벽히", "모범 사례")이 끼어들 수 있습니다. agy에 "틀린 곳을 고쳐"라고만 하면 거의 찾지 못합니다. 그래서 기계가 먼저 의심 문장을 짚어 줍니다.

1. 다시 쓴 글을 문장 단위로 나누고 번호를 붙입니다.
2. 문장마다 원문에 없는 단어, 원문에 없는 숫자, 원문에서는 코드가 아니던 코드 모양을 찾아 **의심 목록**을 만듭니다.
   - 원문에서 '추정'이나 '확인된 사실'이 붙은 내용을 단서 없이 다시 말한 문장(요약에서 흔함)도 넣습니다. 단서가 붙은 문장이나 그 앞 문장과 이웃한 두 단어가 같으면 올립니다.
   - 빠진 숫자·코드 자리·단서도 그것이 있던 원문 문장과 함께 넣습니다. 다시 쓴 글에 그대로 남지 않은 문장을 먼저 보여 줍니다.
3. 원문, 번호 붙인 글, 의심 목록을 agy에 주고, 고칠 문장만 `[12] 고친 문장`, `[12] (삭제)`, `[12+] 뒤에 넣을 문장` 형식으로 받습니다. 글 전체를 다시 받지 않아서 빠릅니다.
4. 고친 글도 아래 검사를 모두 통과해야 합니다. 두 번째 단계가 실패하거나 고친 글이 검사에 걸리면, 첫 번째 글이 검사를 통과한 경우에 그 글을 보여 줍니다.

원문에 없는 단어는 후보일 뿐입니다. 대부분은 쉬운 말로 바꾼 것이라, 원문 뜻과 같으면 그대로 두라고 지시합니다.

2026-09-25에 Gemini가 한 번에 자유롭게 다시 쓴 글(원문에 없는 말이 들어간 곳 12곳, 빠진 단서 5개)로 재 본 결과입니다. 일회성 `agy -p`, Flash Low, 한 번씩입니다.

| 두 번째 단계에 준 것 | 걸린 시간 | 단서 | 없던 숫자 | 뜻이 틀린 문장 |
|---|---|---|---|---|
| 의심 목록 (단어 포함) | 10.1초 | 5/5 되살림 | 2/2 고침 | 10곳 중 5곳 고침 |
| 숫자·단서만 | 10.2초 | 5/5 되살림 | 2/2 고침 | 10곳 중 1곳 고침 |

놓친 곳은 모두 숫자나 단서 없이 단어만 틀린 문장(과장, 틀린 전문 용어)이었습니다. 같은 날 지금 지시문의 초안으로 원문을 처음부터 다시 구성하게 했을 때는 140문장 중 15문장만 의심 목록에 올랐고, 두 번째 단계도 고칠 것이 없다고 답했습니다.

## 무엇을 검사하나

다시 쓴 답은 아래 검사를 모두 통과해야 화면에 나옵니다. 빠진 숫자·코드 자리·단서와 원문에 없는 숫자·경로·코드는 두 번째 단계에서 고치게 하고, 그 밖의 문제에 걸리면 틀린 점을 알려 주고 한 번 더 다시 쓰게 하고, 그래도 걸리면 원문과 한 줄 설명이 나옵니다.

- **코드, 링크, URL, 파일 경로는 agy에 보내지 않습니다.**
  - 코드 블록, 인라인 코드, 마크다운 링크, URL, 파일 경로(`/etc/app.conf`, `~/notes.md`, `src/app/main.py` 등)를 `⟦0⟧` 같은 자리 표시로 바꿔서 보냅니다.
  - 돌아온 글에는 자리 표시가 모두 있어야 합니다. 코드 블록 자리는 정확히 한 번, 혼자 한 줄에, 원래 순서대로 있어야 합니다. 인라인 자리는 요약 등에서 한 번 더 나와도 됩니다.
  - 그다음 원래 내용을 글자 하나 다르지 않게 되돌려 넣습니다. 그래서 이 부분은 바뀔 수 없습니다. 인라인 부분은 문장 안에서 자리를 옮길 수 있습니다.
  - 빗금으로 이은 영문 대문자 약어나 한글 단어(`TCP/IP`, `HTTP/HTTPS/TLS`, `입력/출력`)는 경로가 아니라 문장으로 봅니다.
  - 경로와 URL에 한글이 있어도 전체를 보호합니다(`~/문서/설정.json`). 영어 이름이나 확장자 바로 뒤의 조사(`README를`, `설정.json에`)는 문장으로 남깁니다. 한글 이름 뒤의 조사(`~/문서에`)는 이름과 구분할 수 없어서 경로와 함께 보호합니다.
- **숫자**는 문장이 숫자를 중심으로 쓰이므로 글에 남겨 둡니다.
  - 원문의 숫자가 부호까지 같게, 적어도 나온 횟수만큼 다시 나와야 합니다. `-3`이 `3`이 되거나, 두 번 나온 `3` 중 하나가 빠지면 걸립니다. 요약에서 같은 숫자를 한 번 더 쓰는 것은 허용합니다.
  - 원문에 없는 숫자가 생겨도 걸립니다. 한글로 쓴 수를 숫자로 바꾼 경우(세 가지 → 3가지)도 포함됩니다.
  - 천 단위 쉼표를 빼는 것(1,024 → 1024), 목록 번호를 글머리 기호로 바꾸는 것, 제목에 번호(`## 1.`)를 붙이는 것은 허용합니다.
  - 제목의 장·절 번호(`### 3장: 설계`)를 빼는 것도 허용합니다. 자유롭게 다시 구성하면 장이 다시 묶이기 때문입니다.
- **단서**: '추정', '확인된 사실', '확인한 사실', '일반적인'이 원문에 나온 횟수보다 적게 나오면 걸립니다. 확실하지 않은 내용이 확실한 것처럼 바뀌지 않게 하려는 것입니다.
- **지어낸 것**: 원문에 없는 코드 블록, 인라인 코드, 링크, URL, 경로가 생기면 걸립니다. 원문에 있던 단어에 백틱만 두르는 것은 허용합니다.
- **길이**: 자리 표시를 뺀 본문 길이가 원문의 절반에서 두 배 사이여야 합니다.
- 원문에 이미 `⟦숫자⟧` 표기가 있으면(이 플러그인을 설명하는 답변 등) 코드처럼 보호합니다. 자리 표시와 헷갈리지 않습니다.

검사로 잡을 수 없는 것도 있습니다.

- 같은 종류의 값끼리 자리가 바뀐 경우. "A는 10, B는 20"이 "A는 20, B는 10"이 되어도 숫자 목록은 같습니다.
- 한 곳에서 숫자가 빠졌는데 같은 숫자가 요약 등 다른 곳에 한 번 더 나온 경우
- 원래 자리에는 단서가 있는데, 요약 등 다른 곳에서 같은 내용을 단서 없이 말한 경우. 두 번째 단계에 짚어 주지만, 겹치는 단어로 찾기 때문에 다 찾지는 못합니다.
- 숫자, 코드, 링크, 경로, 단서는 그대로인데 문장의 뜻이 달라진 경우. 두 번째 단계가 찾아 고치게 하지만, 위 표처럼 다 잡지는 못합니다.
- 빗금이 하나이고 확장자가 없는 상대 경로(`docs/README`, `docs/초안`). `TCP/IP`나 `입력/출력`과 모양이 같아서 문장으로 남기고, 그 안의 숫자만 검사합니다.

정확한 표현이 중요할 때는 `/export`나 대화 기록에서 원문을 보세요.

## 동작 방식

```
Claude가 답변을 스트리밍 ──► 훅 (hooks/run → agy_readable/hook.py)
   중간 전송마다: 새 줄을 저장하고 화면에는 아무것도 표시하지 않음
   마지막 전송: 줄을 합치고 코드·링크·경로를 자리 표시로 바꿈
        ──► 데몬 (유닉스 소켓) ──► 미리 띄워 둔 agy (stream-json 모드)
                                   agy 프로세스 하나가 답변 하나만 처리하고 종료
   ① 자유롭게 다시 구성한 글 받기
   ② 의심 문장을 짚어 주고 원문과 맞춰 고칠 줄만 받기 (agy 한 번 더, 새 프로세스)
   자리 표시·숫자·단서·길이 확인 ──► 걸리면 틀린 점을 알려 주고 ①부터 한 번 더 (시간이 남을 때)
   원래 내용 되돌려 넣기 ──► 다시 쓴 답변, 또는 원문 + 한 줄 설명
```

- **데몬을 쓰는 이유.** agy는 시작할 때 로그인, 할당량 확인, 대화 준비에 5~10초가 걸립니다. 백엔드가 느리면 30~60초도 걸립니다. 작은 백그라운드 프로세스(`python3 -m agy_readable.daemon`)가 agy 하나를 미리 띄워 두므로, 다시 쓰는 데는 모델이 답하는 시간만 듭니다.
  - 데몬이 꺼져 있으면 답변의 첫 전송 때 켜집니다.
  - 30분 동안 쓰이지 않으면 대기 중인 agy와 함께 종료됩니다.
- **맥락이 쌓이지 않습니다.** agy 프로세스 하나는 답변 하나만 다시 쓰고 종료됩니다. 그래서 앞 답변의 내용이 다음 답변에 섞이지 않습니다. 하나를 쓰면 바로 새 것을 띄웁니다.
- **백엔드 지연 대비.** agy 백엔드는 가끔 프로세스 하나만 30~60초 멈추게 하고, 다른 프로세스는 멀쩡합니다. 그래서 요청을 다른 agy에도 보냅니다.
  - 약 8초 안에 답이 없을 때 (긴 답변, 자유롭게 다시 구성하는 첫 단계는 더 기다림), 또는 agy가 실패했을 때 하나를 더 씁니다. 요청 하나에 최대 셋까지입니다.
  - 대기 중인 agy가 20초가 지나도 준비되지 않으면 옆에 하나를 더 띄웁니다.
  - 가장 먼저 온 답을 쓰고 나머지는 종료합니다.
- **데몬에 연결할 수 없으면** 훅이 일회성 `agy -p`를 대신 실행합니다.

**걸리는 시간.** 두 단계라서 문장만 다듬던 0.3.x보다 대략 1.5~4배 걸립니다. 2026-09-25에 일회성 `agy -p`, Flash Low로, 두 단계를 합쳐(첫 단계 + 두 번째 단계) 쟀습니다.

| 길이 | 이 버전 | 0.4.0 이전 초안 |
|---|---|---|
| 792자 | 18.1초 (10.1 + 8) | 27.1초, 26.8초 |
| 2,176자 | 16.4초 (9.7 + 6.7) | 35.7초, 37.7초 |
| 5,354자 | 19.2초 (13.2 + 6) | 48.1초, 57.8초 |

- 이전 초안이 느렸던 것은 주로 다시 시도 때문이었습니다. 그 원인(제목의 장 번호, `HTTP/HTTPS/TLS`를 경로로 본 것)은 이 버전에서 고쳤습니다.
- 한 번의 요청은 첫 단계 7.7~26초, 두 번째 단계 6~19.1초로, 실행마다 차이가 큽니다.
- 0.3.x는 미리 띄운 agy로 1,000자 미만 4.7초, 2,500~5,000자 8.2초였습니다(`hook.log` 중간값). 5,354자 답변은 일회성으로 13.8초였습니다.
- 미리 띄운 agy를 쓰면 일회성보다 몇 초 빠르고, 답이 늦으면 다른 agy를 하나 더 띄워 경주시킵니다.

Flash High는 문장만 다듬는 데도 5,354자 답변에 43.7초와 84.4초가 걸려서 이 방식에는 맞지 않습니다. 기본값은 Low입니다.

## 설정

설치할 때, 또는 나중에 `/plugin` → agy-readable → configure에서 바꿉니다.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `model` | `gemini-3.8-flash-low` | 다시 쓸 때 쓰는 모델. `agy models`로 목록을 봅니다. |
| `timeout` | `60` | 두 단계를 합쳐 agy를 기다리는 시간(초). 넘으면 원문을 보여 줍니다. |
| `review` | `true` | 두 번째 단계(원문과 맞춰 고치기). 끄면 빠르지만 원문에 없는 말을 고치지 않습니다. |
| `notes` | `true` | 원문을 보여 줄 때 붙는 한 줄 설명 |
| `retries` | `1` | 검사에 걸린 글을 틀린 점을 알려 주고 다시 쓰게 하는 횟수. `0`이면 바로 원문 |
| `keep` | `20` | 원문과 다시 쓴 글을 비교용으로 남겨 둘 개수. `0`이면 남기지 않음 |

환경 변수가 위 설정보다 우선합니다. 환경 변수로만 바꿀 수 있는 것도 있습니다.

- `AGY_READABLE_MODEL`, `AGY_READABLE_TIMEOUT`, `AGY_READABLE_REVIEW`, `AGY_READABLE_NOTES`, `AGY_READABLE_RETRIES`, `AGY_READABLE_KEEP`
- `AGY_READABLE_AGY`: agy 경로
- `AGY_READABLE_BROWSER`: 로그인 페이지를 여는 명령 (`none`이면 링크만 표시)
- `AGY_READABLE_MIN_CHARS` (300), `AGY_READABLE_MAX_CHARS` (6000)
- `AGY_READABLE_DAEMON=0`: 답변마다 일회성 `agy -p`를 실행하고, 백그라운드에 아무것도 남기지 않음
- `AGY_READABLE_SPARES` (1), `AGY_READABLE_IDLE_EXIT` (1800초), `AGY_READABLE_HEDGE_AFTER` (8초), `AGY_READABLE_STUCK_AFTER` (20초)
- `AGY_READABLE_PART_WAIT` (10초): 늦게 오는 답변 조각을 기다리는 시간

지시문은 첫 단계가 [`agy_readable/prompt_ko.txt`](agy_readable/prompt_ko.txt), 두 번째 단계가 [`agy_readable/prompt_review_ko.txt`](agy_readable/prompt_review_ko.txt)에 있습니다.

## 상태 확인

Claude Code는 플러그인의 `bin/`을 Bash 도구의 PATH에 넣습니다. 그래서 세션 안에서 바로 쓸 수 있습니다. 셸에서는 전체 경로로 실행하세요.

```
agy-readable status    # 설정, agy, 로그인 상태, 데몬, 최근 답변 10개의 결과
agy-readable login     # agy 로그인 (터미널에서는 코드도 직접 물어봄)
agy-readable log 50    # 훅 로그 마지막 50줄
agy-readable samples   # 남겨 둔 원문·다시 쓴 글 목록 (최신이 1번)
agy-readable diff 1    # 1번 글에서 다시 쓰며 바뀐 줄
agy-readable stop      # 데몬과 대기 중인 agy 종료 (다음 답변 때 다시 켜짐)
```

로그와 임시 파일은 플러그인 데이터 폴더(`~/.claude/plugins/data/agy-readable-agy-readable/`)에 있습니다.

- `hook.log`, `daemon.log`: 길이, 시간, 결과, 토큰 수만 적습니다. 답변 자체는 적지 않습니다. 단, "바뀜" 설명에는 바뀐 코드나 숫자가 항목당 30자까지 들어갑니다.
- `state/`: 아직 쓰는 중인 답변의 줄을 담고, 답변이 끝나면 지웁니다. 중간에 끊긴 답변의 파일은 한 시간 뒤에 지웁니다.
- `samples/`: 최근 20개(`keep`)의 원문과 다시 쓴 글입니다. 첫 단계 글(`draft`), 두 번째 단계가 한 일(`review`)과 그 답(`fixes`)도 함께 남깁니다. 검사에서 버린 글도 agy가 쓴 그대로(자리 표시가 든 채로) 남깁니다.
  - 본인만 읽을 수 있습니다(폴더 700, 파일 600). 개수를 넘으면 오래된 것부터 지웁니다.
  - `agy-readable samples`와 `diff`로 봅니다.

## 비용과 개인정보

- **답변이 Google로 전송됩니다.** 다시 쓰는 답변은 모두 agy를 거쳐 본인 Antigravity 계정으로 Google Gemini 서비스에 보내지고, 그 약관을 따릅니다. 이것이 허용되지 않는 환경에서는 설치하지 마세요.
- **할당량.** agy가 자체 시스템 프롬프트를 붙이기 때문에, 요청 한 번에 입력 토큰이 약 14,500개 + 보낸 글 길이만큼 듭니다. 답변 하나에 요청이 두 번이고, 두 번째 요청에는 원문과 다시 쓴 글이 함께 들어갑니다. 본인 Antigravity 할당량에서 나갑니다. 요청을 여러 agy에 보내면 2~3배가 듭니다.
- 검사에 걸려 다시 쓰게 하면 그만큼 할당량이 한 번 더 듭니다.
- **이 컴퓨터에 남는 것.** 최근 20개 답변의 원문과 다시 쓴 글이 `samples/`에 남습니다. 원하지 않으면 `keep`을 `0`으로 두세요.
- 데몬이 켜져 있는 동안(마지막 답변 후 최대 30분) agy 프로세스 하나가 백그라운드에서 대기합니다.

## 한계

- Claude가 답을 쓰는 동안에는 아무것도 보이지 않습니다. 답변이 끝나야 나타납니다.
- 한국어 전용입니다. 지시문과 검사가 한국어 답변에 맞춰져 있습니다.
- 같은 종류의 값끼리 자리가 바뀌거나 뜻이 달라진 것은 검사로 잡지 못합니다. 두 번째 단계가 고치게 하지만 모두 잡지는 못합니다([무엇을 검사하나](#무엇을-검사하나)).
- Claude에 저장되는 답변은 바뀌지 않습니다. 답변 복사, `/export`, 대화 기록에는 원문이 들어갑니다.
- 두 단계라서 답변이 뜨기까지 문장만 다듬을 때보다 2~3배 걸립니다. agy가 느리면 제한 시간(기본 60초)만큼 기다린 뒤에 원문이 나옵니다.
